#维护者更新题目

*题目放在 GitHub 的 Markdown 文件里。** 文件合并到 `main` 后，网站会自己更新；不需要登录网站后台。
## 上传第三周的题目为例

1. 打开[题目文件夹](https://github.com/Praymo/qtia-open-quant-handbook/tree/main/content/questions)，点 **Add file → Create new file**。
2. 在文件名栏输入 `week-03/03-1-card-problem.md`。这是第三周第一题的示例文件名；后面的英文短名可以换，`03-1` 要和题号 `03.1` 对上。GitHub 会自动创建 `week-03` 文件夹。
3. 打开[题目模板](../templates/question.md)，复制全文，粘贴到新文件里。改最上面的题名、摘要、发布日期或(贡献者)，再写“中文题目”和“English version”里的题面。检查双语的数字、条件和小问要一样。
4. 点 **Commit changes...**，选择“创建新分支”。分支可以理解为一份待检查的草稿。随后点 **Propose changes**，发起 Pull Request（简称 PR）。PR 是让改动先经过检查、再合并到正式网站。
5. 在同一分支打开 [`src/data/week-credits.json`](../src/data/week-credits.json)，照第二周新增第三周的整理与审核名单；再把同样的名单加到 README 开头的中英文贡献表。对外只写“姓氏＋名字拼音首字母”，审核名单按姓氏拼音排序并注明排名不分先后。
6. 在 PR 页面等 **Checks** 变绿，检查题目和署名后点 **Merge**。几分钟后，打开[第三周页面](https://praymo.github.io/qtia-open-quant-handbook/week/03/)核对。周次、题数和题库筛选会自动更新。

第三周第二题照着做，文件名以 `03-2-` 开头，题号填 `03.2`。如果要把几道题放进同一个 PR，创建下一道题时先切到刚才的分支，再新建文件。

## 模板最上面的字段怎么填？

| 字段 | 第三周第一题示例 | 说明 |
| --- | --- | --- |
| `id` / `week` | `"03.1"` / `3` | 题号和周次；要与 `week-03` 文件夹一致。 |
| `origin` | `official` | QTIA 每周题目填 `official`；经社区投稿收录的题目填 `community`。 |
| `submittedBy` / `relatedTo` | 可选 | 社区题目可注明投稿人；若从已收录题目延伸，`relatedTo` 填原题号，例如 `"02.3"`。 |
| `title` / `titleEn` | 中英文题名 | 用真实题名替换模板。 |
| `summary` | 一句话摘要 | 介绍问题，不剧透答案。 |
| `date` | `"2026-09"` | 发布的年月 |
| `category` | `algorithm` | 也可选 `probability` 或 `brainteaser`。 |
| `difficulty` | `D2` | 可选 `D1` 到 `D5`，或 `Optional`。 |
| `tags` | `[number-theory]` | 保留一个简短英文主题词即可。 |
| `contributors` | `["你的GitHub用户名"]` | 只填直接修改这道题的 GitHub 贡献者；每周整理、审核名单另填 `week-credits.json`。如果还没确定，可以用空列表 `[]`。 |

题目正文只放题面和来源。记录 QTIA 分享来源；有人提交解答时，把每一种解法放在 `content/solutions/题号/` 的独立文件里，网站会把它们排在同一道题下。

## 只想改一道旧题？

打开那道题的网页，点“编辑题目”，修改后同样创建分支和 PR。中英文有一处数字或条件变化时，记得核对另一种语言。已经公开的 `id` 尽量别改，它也是网址的一部分。

## PR 检查没通过怎么办？

点开失败的 **Checks** 看提示的文件和字段。常见原因是文件夹、题号和 `week` 对不上，或者中文题面与 English version 有一处空着。修改同一个分支即可，检查会自动重跑。如果只在 GitHub 网页编辑，不需要在电脑上运行命令。

## 新的一周怎么开反馈？

到仓库的 [General 讨论分类](https://github.com/Praymo/qtia-open-quant-handbook/discussions/categories/general)，为新的一周创建一个“第 X 周 · 自由讨论”话题，题目、答案、建议都可以在这里聊。然后打开 [`src/data/feedback.json`](../src/data/feedback.json)，在 `weeks` 末尾加一行，例如 `{ "week": 3, "discussion": 9 }`；`discussion` 填新话题链接末尾的实际编号。不要照抄示例编号。

`questions` 里是各周共用的三道反馈题，不用每周复制。网站会自动生成这一周的反馈表；读者一次选完三项，去 GitHub 确认一条 Issue，公开结果和自由讨论留言约每小时同步。如果不确定 JSON 怎么改，可以在 PR 中贴自由讨论链接，请熟悉仓库的同学帮忙填写。

## 上线后看哪里？

打开这一周的题目页，检查题目、展开后的英文、公式和底部反馈入口。再看[题库](https://praymo.github.io/qtia-open-quant-handbook/questions/)能否按周次找到新题。如果有问题，继续改原文件并提交；不要另建一个同题号文件。
